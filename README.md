## 一、为什么要改

原版程序在检测到某门课程的待学课时为 0 时，会自动进入“复习模式”，把所有已完成的课时重新播放一遍，而且控制台没有任何提示。结果是课程早就学完了，程序还在反复重播，使用者却完全不知道发生了什么。

本版本针对这个问题做了修改。

## 二、本次修改内容

1. **一轮流程，不再单独预检**
   程序按配置顺序逐门处理：有待学课时就开始学；待学课时为 0 就记为已完成，直接进入下一门，不播放、不停留。

2. **完成记录，自动跟进新增课时**
   每门课程的结果写入 `data\course_state.json`（只保存课程链接、课程名、状态和更新时间）。
   每次启动仍会逐门打开课程检查：只有「原本已完成、现在又出现待学课时」的课程才会被改回“未完成”并继续学习；一直没学完的课程记录保持原样，不需要手动删除文件。
   课程全部学完后再次运行，程序只会快速核对一遍目录，不会播放。

3. **本轮结束汇总**
   一轮结束后打印每门课程的结果，只有两种状态：

   ```
   [INFO] 课程 1/3: 高等数学 -> 已完成
   [INFO] 课程 2/3: 大学英语 -> 已完成
   [INFO] 课程 3/3: 线性代数 -> 未完成
   ```

4. **全部学完才询问复习**
   本轮所有课程都完成时，才会在控制台询问：

   ```
   所有课程均已学完, 是否复习(重新播放已完成的课时)? [y/N]:
   ```

   - 输入 `y` / `yes` / `是`：重新打开浏览器，重播已完成的课时；
   - 直接回车或输入其它内容：退出程序，本次不播放任何内容。

   只要还有课程没学完，就不会询问，也不会自动复习。

5. **按“单个课时”学习，不再按“xx.xx 章节标题”**
   原版把目录里的章节标题行（如 `1.1 xxx`、`1.2 xxx`）当作学习单位，而且融合课的章节容器和课时行共用同一个 class，导致按章节走、课时重复、序号错位、点击落在容器上、进度读不到而误报“未确认播放完成”。
   本版改为定位真正的课时节点（单片视频），并排除内部还嵌套着课时的父容器。目录里一个课时只算一个条目，不会重复计数；播放逻辑沿用原版：视频播完但平台进度不足 100% 时，会自动回退到对应进度点重播，直到上报完成（最多自动重试 2 次）。

6. **异常保护**
   课程页异常、目录中识别不到课时时，按“未学完”处理，避免误判成已学完而弹出复习询问。

7. **启动横幅**
   显示 `modified by sylvia9001`，标明这是修改版。

## 三、程序功能（沿用原版）

- 自动登录，自动通过登录滑块验证（可选）
- 自动播放、自动切换下一集
- 自动跳过弹窗和弹题
- 自动静音，可设置倍速
- 自动检测暂停并续播
- 支持智慧共享课、翻转课、融合共享课
- 支持刷习惯分
- 支持隐藏窗口后台运行
- 学时统计、实时进度、各种自定义配置

## 四、运行方式

1. 系统要求 Windows 10 及以上。
2. 用文本编辑器打开 `config.ini`，填写账号、密码和课程链接（也可以留空，启动后手动登录并手动进入课程）。
3. 双击 `Autovisor.exe` 运行。
4. 首次运行需要登录，登录状态保存在 `data\cookies.json`，**这个文件等同于免密登录凭证，不要发给别人**。
5. 每门课程的完成状态记录在 `data\course_state.json`，仅供查看；每次启动都会重新核对该课程有没有新课时。

### 目录说明

| 文件 / 目录 | 说明 |
| --- | --- |
| `Autovisor.exe` | 主程序 |
| `internal\` | 程序运行所需的 Python 运行时和依赖，不可删除 |
| `packages\` | OpenCV / NumPy 等可选组件 |
| `resources\` | 图标、脚本等资源 |
| `config.ini` | 配置文件（账号、课程链接、播放参数） |
| `data\` | 运行数据：`cookies.json`（登录凭证）、`course_state.json`（完成记录）等，**分享前请删掉 `data\cookies.json` 和 `data\course_state.json`** |
| `logs\` | 运行日志，程序启动后自动创建 |
